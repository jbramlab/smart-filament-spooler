# Spooler Firmware Plan

Oct 20, 2026

The firmware is split into small modules around one state machine, with a fast control loop and a separate screen task. Planning the pins showed the original ESP32 is too tight, so this plan moves to an ESP32-S3.

## Platform and tools

**Board: ESP32-S3-DevKitC-1 (N16R8 variant), in place of the classic ESP32.** The design needs about 22 signal pins. A classic ESP32 DevKit has about 20 pins that are safe to use once the boot and flash pins are excluded, so the last few would have to share boot pins. The S3 has about 25 free pins, native USB and 8 MB of extra RAM (PSRAM), which LVGL uses for smooth screen buffers. It costs about £2–3 more.

**Decision needed:** if you agree, the proposal's bill of materials and "alternatives considered" table should change from ESP32 to ESP32-S3. The budget then sits right at £100, so check the technicians' stock first.

**Traverse motor change:** drive the traverse through a second step/direction driver (a TMC2209 or A4988) instead of the ULN2003 board. That uses 2 pins instead of 4 and gives smoother movement. A 28BYJ-48 can be converted to work with these drivers, or a small NEMA 14 can be used.

**Toolchain:** VS Code with PlatformIO, Arduino framework. PlatformIO pins library versions in one file, so the build is repeatable for the open-source release.

| Library | Used for | Note |
| --- | --- | --- |
| FastAccelStepper | Step pulses for both motors, generated by the chip's hardware timers | Smooth motion even while the screen is busy |
| TMCStepper | Setting up the TMC2209 over UART and reading its stall value | Stall reading is slip check 3 |
| AS5600 (Rob Tillaart) | Reading the measuring wheel's magnetic encoder over I2C | 4096 counts per turn |
| ESP32Servo | Servo signal for the tension brake |  |
| LVGL | Touchscreen buttons, menus and progress bars | Use the version that matches the display driver |
| TFT\_eSPI or LovyanGFX | Driving the ILI9341 screen and XPT2046 touch | Check which one works with the current ESP32-S3 Arduino core before committing |
| Preferences (built in) | Saving material and spool profiles in flash | Survives power-off |

## Modules

Each module owns one piece of hardware or one job, and only talks to the others through small functions. That keeps each one testable on its own during bring-up.

| --- | --- | --- | --- |
| `config.h` | Pin numbers, gear ratio, wheel diameter, default limits |  |  |
| `profiles` | Material profiles (grams per metre, tension target, max speed, splice temperature) and saved spool profiles | Flash storage | Flash storage |
| `winder` | Receiving-spool motor: speed, holding, stall value | TMC2209 over UART | Step pulses |

| `length` | Metres wound and filament speed from the measuring wheel | AS5600 |  |

## Control loops, timing and calculations

The safety checks and motor control run in their own task, so a slow screen redraw can never delay a stop.

| Task | Rate | What it does | Core |
| --- | --- | --- | --- |
| Step generation | Hardware timers | Pulses for both motors | None |
| Control | 100 Hz | Reads the wheel, updates radius and motor speed, moves the traverse, runs the tension PID, runs safety checks, steps the state machine | 1 |
| Screen | LVGL tick every 5 ms, redraw about 30 times a second | Touch input and screens | 0 |
| Logger | 10 Hz | One line of data over USB | 0 |

### Length and grams

```latex
L = \frac{N}{4096} \cdot \pi d_w \cdot k_{cal}
```

N is the total encoder count, d\_w the wheel diameter and k\_cal a calibration factor from the 10 m test (O2). Grams wound = L × the material's grams per metre.

### Spool radius

The radius is predicted from the layer count, then checked against the wheel:

```latex
r = r_{core} + \left\lfloor \frac{n}{n_{layer}} \right\rfloor p
```

n is spool turns so far, n\_layer the turns per layer (inside width ÷ filament diameter, 36 for a Bambu spool) and p the layer pitch, about 1.52 mm for 1.75 mm filament. A slow drift between prediction and wheel updates the estimate. A sudden gap is treated as slip.

### Motor speed for a steady filament speed

```latex
f_{steps} = \frac{v \, G \, S}{2 \pi r}
```

v is the filament speed, G the gear ratio (3), S the steps per motor turn (200 × microstepping) and f\_steps the step rate. The motor slows down as the spool grows, so the filament speed stays constant.

### Slip check

```latex
s = \frac{\Delta L_{wheel}}{2 \pi r \, \Delta n}
```

Normally s is close to 1. If it stays below a threshold (start with 0.8 for 0.5 s, then tune) the machine flags slip. The TMC2209 stall value is a second, independent check.

### Tension PID

```latex
u = K_p e + K_i \int e \, dt + K_d \frac{de}{dt}, \quad e = \theta_{target} - \theta_{dancer}
```

u is the servo brake angle, clamped to its safe range, with anti-windup on the integral. Tune P first, then add I to remove steady error, and only add D if it overshoots.

### End catch and snap

When the runout switch opens, the machine checks the source spool's estimated remaining length. Near zero means the end of the spool: it winds the known path length from the switch to the receiving spool, minus 5 cm, then holds. Otherwise the filament has snapped: the brake clamps and both motors hold.

### Splicer heater

Start with on/off control and about ±3 °C hysteresis around the material's set point, and move to PID only if it overshoots.

## Safety interlocks

The firmware starts every power-up in a safe state and has several independent ways to turn the heater off. These back up the hardware thermal fuse; they do not replace it.

| Interlock | Trigger | Action |
| --- | --- | --- |
| Safe start-up | Power-on or reset | Heater off, motors disabled until the user presses Start |
| Stop button | Tapped on any screen | Paused: motors hold, heater off |
| Heater only when paused | Any state except Splice | Heater output forced off |
| Maximum heat time | Heater on longer than a set limit (to set in testing) | Fault |
| Thermal runaway | Temperature rises too slowly while heating, e.g. the thermistor has fallen out | Fault |
| Sensor out of range | Thermistor reads open or short circuit | Fault |
| Motor current limit | Set in the TMC2209 at start-up | Limits the force at pinch points |
| Watchdog | Control task stops responding | Chip resets into the safe start-up state |

The exact limits (heat time, temperature-rise rate) are set during makerspace testing and recorded in `config.h`.

## Bring-up order

Get one part working at a time, in the order the parts are needed. Each step has its own small test program.

1. ESP32-S3 blink and serial output: proves the toolchain works.
2. Screen and touch showing a test button in LVGL.
3. AS5600 reading while the wheel is turned by hand; work out counts per metre.
4. Winder motor through the TMC2209 at a fixed speed; read its stall value.
5. Traverse motor and endstop homing.
6. Runout switch and hall sensor.
7. Everything together, winding at a steady filament speed: milestone M1.
8. Dancer potentiometer reading and a servo sweep.
9. Tension PID on light and heavy spools.
10. Heater and thermistor, in the makerspace after the risk assessment.
